### Шаг 1: Установка Samba
Если Samba еще не установлена, обновите списки пакетов и установите необходимые пакеты:
```
apt-get update
apt-get install samba samba-client
```

### Шаг 2: Создание каталога для общего доступа и настройка прав
Создадим папку, которую будем расшаривать, и специальную группу для управления доступом на уровне файловой системы.

```
# Создаем каталог
mkdir -p /srv/samba/shared

# Создаем группу для пользователей, имеющих доступ к этой папке
groupadd smbusers

# Назначаем владельца (root) и группу (smbusers) для каталога
chown root:smbusers /srv/samba/shared

# Устанавливаем права: владелец и группа имеют полный доступ, остальные - никакой
chmod 770 /srv/samba/shared
```

### Шаг 3: Создание системных пользователей
Создадим двух пользователей: `user_rw` (чтение и запись) и `user_ro` (только чтение). 
*Флаг `-s /sbin/nologin` запрещает им вход в систему по SSH, что безопаснее, но они смогут подключаться по SMB.*
```
# Создаем пользователей
useradd -s /sbin/nologin user_rw
useradd -s /sbin/nologin user_ro

# Добавляем обоих пользователей в группу smbusers (для базового доступа к папке)
usermod -aG smbusers user_rw
usermod -aG smbusers user_ro
```

### Шаг 4: Добавление пользователей в базу данных Samba
Samba использует собственную базу паролей. Пользователь должен существовать в системе, чтобы его можно было добавить в Samba.
```
# Добавляем пользователей и задаем им SMB-пароли (система попросит ввести пароль дважды)
smbpasswd -a user_rw
smbpasswd -a user_ro

# Активируем учетные записи в Samba
smbpasswd -e user_rw
smbpasswd -e user_ro
```

### Шаг 5: Настройка конфигурационного файла Samba
Сделаем резервную копию конфигурационного файла и отредактируем его:
```
cp /etc/samba/smb.conf /etc/samba/smb.conf.bak
nano /etc/samba/smb.conf
```

Прокрутите файл в конец и добавьте следующий блок настроек для вашего ресурса:

```
[SharedFolder]
    path = /srv/samba/shared
    browseable = yes
    # По умолчанию доступ только для чтения для всех
    read only = yes
    # Исключение: user_rw имеет право на запись
    write list = user_rw
    # Указываем, кто имеет право подключаться к этому ресурсу
    valid users = user_rw, user_ro
    # Принудительно назначаем группу создаваемым файлам и папкам
    force group = smbusers
    # Маски прав для новых файлов и папок, создаваемых через SMB
    create mask = 0660
    directory mask = 0770
```
*Сохраните файл (в nano: `Ctrl+O`, `Enter`, затем `Ctrl+X`).*

### Шаг 6: Запуск и включение служб Samba
Запустите демоны Samba (`smb` отвечает за файлы, `nmb` за разрешение имен в сети):
```
systemctl enable smb nmb
systemctl start smb nmb

#Проверьте статус служб, чтобы убедиться, что они работают:
systemctl status smb
```

### Шаг 7: Настройка брандмауэра (Firewall)
Если на сервере включен брандмауэр (например, `iptables` или `firewalld`), необходимо открыть порты для SMB: **139** и **445** (TCP).

Для `iptables` (стандартный подход в ALT):
```
iptables -A INPUT -p tcp --dport 139 -j ACCEPT
iptables -A INPUT -p tcp --dport 445 -j ACCEPT
# Сохранение правил (зависит от конфигурации ALT, часто используется service iptables save)
service iptables save
```
*Если используется `firewalld`:*
```
firewall-cmd --permanent --add-service=samba
firewall-cmd --reload
```

### Шаг 8: Проверка работы
1. **С локального сервера:**
   Проверьте видимость ресурса:
   ```bash
   smbclient -L localhost -U user_rw
   ```
   (Введите пароль для `user_rw`). Вы должны увидеть в списке шару `SharedFolder`.

2. **С клиентского компьютера (Windows/Linux):**
   - Подключитесь к серверу по адресу `\\IP_АДРЕС_СЕРВЕРА\SharedFolder`.
   - При входе под **user_rw**: попробуйте создать файл или папку. Это должно получиться.
   - При входе под **user_ro**: попробуйте создать файл. Система должна выдать ошибку "Отказано в доступе" (Access Denied), но вы сможете открывать и копировать существующие файлы.

### Важные примечания:
- Если пользователи уже существовали в системе, просто пропустите шаг `useradd` и сразу добавьте их в группу `smbusers` и базу `smbpasswd`.
- Параметр `force group = smbusers` в конфиге критически важен: он гарантирует, что любые файлы, созданные пользователем `user_rw`, будут принадлежать группе `smbusers`, и права `770` на каталог продолжат корректно работать.
